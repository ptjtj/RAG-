产品需求文档（PRD）

项目：ai-knowledgeStock — AI 知识库管理与问答平台
作者：产品经理（基于代码库分析）
日期：2026-05-15

一、产品概述
本项目是一个轻量级企业级 AI 知识库（KB）管理与问答示例，包含前端管理控制台（ai-kms）与后端服务（backend）。功能覆盖知识库管理、文档上传与解析、向量化嵌入、语义检索（RAG）、会话管理与用户管理，旨在为企业或个人提供文档驱动的问答能力与知识管理工作流。

二、目标与成功标准
目标：

- 提供可上传、解析并向量化的知识库管理系统，支持高质量语义检索与基于上下文的问答。
- 提供易用的前端管理控制台，方便非技术用户管理知识库与查看来源。

成功指标（KPI）：

- 文档上传后完成向量化并可查询的平均时长 < 60s（在本地环境与中等文档负载下）。
- 用户会话满意度 >= 80%（通过采样问卷或人工打分）。
- 检索返回的 Top-3 片段包含正确来源比例 >= 90%（测试集验证）。
- 系统稳定运行 99% 可用（非生产环境目标可放宽）。

三、目标用户与用户场景
目标用户：企业知识管理人员、研发/支持团队、产品/销售人员、研究人员及技术爱好者。
典型场景：

- 客服从知识库快速检索答案并引用来源；
- 产品经理上传规格文档并基于文档进行问答或生成摘要；
- 团队建立专题知识库并共享问答会话历史。

四、核心功能（详细需求与验收标准）

1. 知识库管理（KB）

- 功能：创建/删除/查看知识库；查看每个知识库下的文档与状态。
- 验收：能够新建 KB 并显示包含文档数量、向量化进度、最近更新时间。

2. 文档上传与解析

- 支持格式：.txt、.docx、.pdf（与现有 parser_service.go 一致）。
- 处理流程：上传 → 计算 MD5 去重 → 异步解析为 chunk → 向量化（embedding）→ 存储向量索引。
- 验收：重复文件在同一 KB 中不会生成新条目；支持异步任务状态查看与重试。

3. 向量化与检索（RAG）

- 使用外部 embedding 与 chat API（受环境变量 DEEPSEEK_API_KEY、ZHIPU_API_KEY 控制）。
- 相似度阈值：当前实现使用余弦相似度并筛选 > 0.4，返回 top-3 chunk 作为上下文。
- 验收：对给定查询能返回关联背景片段并附带来源文件与片段位置；可配置 top-K 与阈值。

4. 问答与会话管理

- 支持会话创建、历史存储、会话删除；前端可查看会话上下文与来源片段。
- 验收：会话能保持上下文（对话轮次关联），并展示用于生成答案的背景片段。

5. 用户与权限

- 支持管理员种子用户（默认 admin/123456），以及用户登录与管理页面。
- 验收：登录流程可用，用户管理页面列出用户并支持基本操作。

6. 前端 UX 要点

- 重要页面：聊天页、知识库管理、文档上传、用户管理。
- 验收：上传流程清晰、有任务进度提示；检索结果展示来源与片段；会话历史可回溯。

五、非功能需求

- 可部署性：后端基于 Go（Gin + GORM），前端基于 Umi Max + TypeScript + Ant Design；支持本地运行与容器化部署。
- 可扩展性：向量服务接口抽象，允许替换不同 embedding / index 实现。
- 安全性：鉴于 License 对商用严格限制，需在 UI 和 README 中明确显示版权与使用条款；对 API 增加身份验证与速率限制以防滥用（当前实现需要补充）。
- 隐私：上传文档可能包含敏感信息，需在生产部署前添加数据加密与访问控制策略（当前代码库无明显加密实现）。

六、系统约束与依赖

- 依赖 MySQL（默认数据库名 ai_kms）与外部大模型/embedding 服务（DeepSeek、智谱等）。
- 环境变量：DB_USER/DB_PASS/DB_HOST/DB_PORT/DB_NAME、DEEPSEEK_API_KEY、ZHIPU_API_KEY。
- 许可与合规：项目 LICENSE 明确禁止商用，需在所有交付物中保留版权声明并提醒团队遵守。



七、风险与缓解

- 外部模型/embedding 服务不可用 → 提供本地 fallback 或排队机制。
- 敏感数据泄露风险 → 在生产前增加加密、访问控制与审计日志。
- 法律风险（许可证限制）→ 与法律/合规确认商业使用边界，或替换为更宽松许可证版本。

八、验收测试用例（示例）

- 上传一个包含多页 PDF 的文档，验证解析为 chunk 并完成向量化；在搜索中能检索到该文档的相关片段。
- 上传同一文件两次，第二次返回去重提示且不重复创建记录。
- 发起一个多轮会话，验证上下文关联并且返回的答案附带 Top-3 来源片段。



- 后端：Go + Gin；解析与向量化在 backend/services 下实现；存储去重基于 MD5。
- 前端：ai-kms 使用 Umi Max + Ant Design + Tailwind，重要页面分别位于 ai-kms/src/pages/chat、/kb、/login、/userManage。
- 现有检索策略：余弦相似度阈值 0.4、返回 top-3 chunk。
- 环境变量与 DB 配置在 README 中有明确说明，部署前需配置 MySQL 与 API keys。



附录：里程碑任务清单（Jira / SQL todos）

MVP（高优先）
- mvp-kb-management：实现知识库创建/删除/列表 API 与前端页面（包括文档计数与向量化状态）。
- mvp-doc-upload：实现文档上传、MD5 去重、异步解析为 chunk（支持 .txt/.docx/.pdf）。
- mvp-vectorization：集成 embedding 服务并将 chunk 向量化入库；实现相似度检索接口（top-K、阈值）。
- mvp-chat-mgmt：实现多轮会话管理、历史存储与答案中展示来源片段。
- mvp-frontend-ux：完善上传进度、检索结果来源展示与基础登录（admin 种子用户）。

M1（中优先）
- async-tasks-panel：异步任务监控面板、任务队列与重试机制。
- user-management：完善用户管理页面与权限控制（增删改查）。
- search-config：检索参数可配置（top-K、相似度阈值、去重规则）。
- monitoring-logs：基本审计日志与错误监控集成（方便定位解析/向量化失败）。

M2（低优先）
- multi-model：支持多模型接入与切换策略（embedding/chat 可选后端）。
- quality-eval：检索质量评估工具与用户反馈收集（答案打分机制）。
- security-audit：敏感数据扫描、加密存储与访问控制增强。
- k8s-deploy：容器化部署模版与 Helm Chart，支持生产就绪部署。
