产品需求文档（PRD）

项目：ai-knowledgeStock — AI 知识库管理与问答平台
作者：产品经理（基于代码库分析）
日期：2026-05-15（更新：2026-05-29）

一、产品概述
本项目是一个轻量级企业级 AI 知识库（KB）管理与问答示例，包含前端管理控制台（ai-kms）与后端服务（backend）。功能覆盖知识库管理、文档上传与解析、向量化嵌入、语义检索（RAG）、会话管理与用户管理，旨在为企业或个人提供文档驱动的问答能力与知识管理工作流。

二、目标与成功标准（可测量）
目标：

- 提供可上传、解析并向量化的知识库管理系统，支持高质量语义检索与基于上下文的问答。
- 提供易用的前端管理控制台，方便非技术用户管理知识库与查看来源。

关键指标（KPI）与测量方式：

- 向量化时延：文档上传后完成向量化并可查询的平均时长 < 60s（测量方法：在标准化环境上传 100 份中等大小文档，取 P95）。
- 用户满意度：用户会话满意度 >= 80%（测量方法：会话结束弹出 1-5 星评分，采样 200 次）。
- 检索准确率：Top-3 返回片段包含正确来源比例 >= 90%（测试方法：固定测试集、离线评估）。
- 可用性：服务 99% 可用（以 30 天为窗口计算可用时间）。

三、目标用户与用户旅程
Persona（示例）：

- 知识管理员（企业）—— 上传规范文档、管理 KB、查看向量化状态、处理重复与冲突。
- 客服专员 —— 快速检索并引用来源片段，创建会话并保存常见问答。
- 产品经理/研发 —— 上传需求/设计文档并进行上下文问答或生成摘要。

关键用户旅程（优先）：上传文档 → 异步解析与向量化 → 查看进度 → 发起检索/会话 → 保存会话与来源引用。

四、详细功能与可验收标准
（对每项增加明确验收条目）

1. 知识库管理（KB）

- 功能：创建/删除/重命名/查看知识库；展示文档数量、向量化进度、最后更新时间。
- 验收：在 UI 新建 KB 并能看到文档计数；删除为软删除并可恢复；支持分页与搜索。

2. 文档上传与解析

- 支持格式：.txt、.docx、.pdf（保持与 parser_service.go 一致，后期扩展支持 PPT、图片 OCR）。
- 流程与容错：上传 → 计算 MD5（或 SHA256）去重 → 入队异步解析并创建 chunk → 向量化 → 写入向量索引；失败自动重试（3 次）并写入任务日志。
- 验收：上传相同文件不重复创建记录；任务面板能展示每个任务状态与错误；支持人工重试。

3. 向量化与检索（RAG）

- 支持配置：可调整 top-K、相似度阈值、去重策略；向量化可切换后端（DeepSeek / 智谱 / 本地）。
- 验收：检索响应中包含匹配分数、来源文件名、chunk 偏移，响应时间在 200ms（内存索引）或 2s（外部索引）。

4. 问答与会话管理

- 功能：创建会话、保存/加载历史、多轮上下文管理、输出引用来源。
- 验收：连续 5 轮对话能保持上下文；会话列表支持导出/删除；答案带来源片段与置信度分数。

5. 用户与权限（安全）

- 身份：基于 JWT 的认证，密码必须以 bcrypt/argon2 哈希存储；禁止在代码/仓库存储明文密钥。
- 权限：实现简易 RBAC（Admin、Editor、Viewer）；种子管理员必须在首次安全初始化中设置强密码，代码中移除弱默认口令。
- 验收：登录失败超过 5 次触发短时封锁；管理员能管理用户并分配角色。

6. 前端 UX 要点

- 上传流程需有任务队列/进度与取消；检索界面展示来源与片段高亮；会话支持导出和收藏。
- 验收：上传后能在任务面板查看状态；检索结果点击跳转到来源片段。

五、安全与合规（必须实施）

- 秘密管理：禁止提交 .env 或密钥到仓库；在 README 明确说明并将 .env 加入 .gitignore；CI 预检 git-secrets。历史中存在密钥需立刻旋转并清理历史（BFG/git-filter-repo）。
- 加密与存储：对敏感字段（API key、私人文件元数据）加密存储；数据库备份需加密。
- 认证与授权：JWT 使用足够随机的 secret，验证签名算法，refresh token 采用可撤销的存储（blacklist）；密码使用 bcrypt/argon2。
- 审计与日志：记录重要操作（上传、删除、登录失败、密钥轮换），日志避免写入明文密钥，并支持审计导出。
- 速率与防滥用：对外 API 增加速率限制和认证；对上传与检索操作限流。
- 法律合规：在 UI 与 README 明确 LICENSE 限制，若需商业使用需联系法律/替换授权。

六、运维与可观测性

- 监控指标：任务队列长度、向量化延迟 P50/P95、请求成功率、错误率、CPU/内存、磁盘使用。
- 告警：向量化延迟超过阈值、队列堆积、外部服务不可用应触发告警并降级服务。
- 备份与恢复：定期 DB 备份（每日）、索引快照；提供恢复步骤文档。

七、API、数据契约与版本管理

- 明确主要 API 接口：/kb、/documents、/search、/chat、/auth，统一返回结构 { code, message, data }，并定义常见错误码（400/401/403/429/500）。
- 幂等性：上传接口返回任务 ID，重复上传相同文件返回相同任务或去重提示；删除操作为软删除。
- 版本策略：对外 API 使用 /v1/ 前缀，重大变更需兼容旧版至少 30 天或通过迁移脚本。

八、性能与容量目标

- 并发：单实例支持 50 并发上传任务（MVP）；按需扩展到 500 并发（K8s）。
- 时延目标：查询响应 < 300ms（内存索引）；向量化单文档 P95 < 60s（预期）。

九、质量保障与测试策略

- 单元测试、集成测试与端到端（上传→解析→检索）覆盖关键路径。
- 自动化验收用例（见第十节）纳入 CI，关键场景在每次主分支合并时运行。

十、验收测试用例（示例）

- 上传多页 PDF，等待任务完成，检索能返回来源片段并确认 chunk 偏移。
- 上传同一文件两次，第二次触发去重逻辑并返回已存在提示。
- 多轮会话（>=5 轮）能保持上下文并且答案包含 Top-3 来源片段。
- 用户权限测试：Editor 无法删除 KB，Admin 能管理用户并撤销 Token。

十一、里程碑与工作拆分（可直接转为 Jira 任务）

MVP（高优先，产出可演示）

- mvp-001 kb-management：KB CRUD API + 前端页面（文档计数、状态）【验收：能创建/删除/列出 KB】
- mvp-002 doc-upload：文档上传 + MD5/SHA256 去重 + 异步解析任务 + 任务面板【验收：上传去重、任务状态可见】
- mvp-003 vectorization：集成 embedding 后端、向量入库、相似度检索接口（top-K）【验收：检索返回带来源】
- mvp-004 chat-mgmt：多轮会话、历史保存、答案来源展示【验收：5 轮上下文保持】
- mvp-005 security-baseline：密码哈希、移除默认弱口令、环境变量 secret 指导文档、CI 秘密扫描【验收：无明文密码、CI 有 git-secrets】

M1（中优先）

- m1-001 tasks-panel：任务队列监控、失败重试机制
- m1-002 user-management：RBAC、用户页面、登录保护策略（账号锁定/重试限制）
- m1-003 monitoring：Prometheus/Grafana 指标 & 基本告警
- m1-004 search-config：检索参数 UI（top-K、阈值、去重规则）

M2（低优先）

- m2-001 multi-model：支持多模型切换与策略
- m2-002 quality-eval：打分与反馈收集、离线评估工具
- m2-003 infra-production：K8s 部署模版与 Helm Chart、CI/CD 完整流水线

十二、风险与缓解（细化）

- 密钥泄露：实施秘密扫描、历史清理、立即轮换与通知流程。
- 外部服务中断：实现本地简单 embedding fallback 或排队并告警。
- 法律/许可证风险：在交付物显著位置提醒 LICENSE，产品上线前完成合规审查。
